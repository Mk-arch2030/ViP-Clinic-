## 4. EXECUTION ORDER

The bounded implementation shall execute in this order:

1. Establish PostgreSQL connection through the existing bounded runtime
   configuration.
2. Execute one controlled schema transaction.
3. Create the CPN sequence.
4. Create the Patient table.
5. Apply only the authorized Patient identity/CPN constraints.
6. Verify the created physical objects and constraints.
7. Commit the schema transaction.
8. Execute independent read-only structural proof.
9. Confirm no unauthorized physical object was introduced.

Schema execution must be atomic.

Failure during schema execution must roll back the schema transaction.

---

## 5. CPN SEQUENCE PLAN

OBJECT:

`clinic_patient_number_seq`

Required properties:

- PostgreSQL sequence.
- Starting value = 1.
- Increment = 1.
- PostgreSQL-authoritative allocation.
- Durable.
- Concurrent-safe allocation.
- Internal technical allocation mechanism.
- Not a Product entity.
- Not a Case/Visit/Clinic Day identifier.
- Sequential does not mean gapless.

No additional sequence is authorized.

---

## 6. PATIENT TABLE PLAN

OBJECT:

`patients`

PHYSICAL NAMING AUTHORITY = POSTGRESQL-PHYSICAL-NAMING-DECISION-V1

Authorized physical column names:

- `patient_id`
- `clinic_patient_number`
- `name`
- `age`
- `profession`
- `phone`
- `gender`

These names are authorized by POSTGRESQL-PHYSICAL-NAMING-DECISION-V1.

Physical types are governed by POSTGRESQL-PHYSICAL-DATA-TYPES-DECISION-V1.

Authorized physical choices:

- `patient_id` = PostgreSQL `UUID`;
- `patient_id` generation = PostgreSQL 18 native `uuidv7()`;
- `clinic_patient_number` = PostgreSQL `TEXT`;
- `name` = PostgreSQL `TEXT`;
- `age` = PostgreSQL `INTEGER`;
- `profession` = PostgreSQL `TEXT`;
- `phone` = PostgreSQL `TEXT`;
- `gender` = PostgreSQL `TEXT`.

No numeric identifier, BIGINT, identity column, or serial mechanism is selected.

---

## 7. CPN CONSTRAINT PLAN

`clinic_patient_number` must be the authorized physical column representing
CPN and must be:

- NOT NULL;
- UNIQUE.

The database uniqueness constraint is authoritative.

The CPN remains distinct from the technical Patient persistence identifier.

---

## 8. PATIENT IDENTITY PLAN

The Patient technical persistence identity must be distinct from CPN.

No implementation may use CPN as the physical primary key.

The technical identifier representation is authorized as PostgreSQL
`UUID` generated by PostgreSQL 18 native `uuidv7()`.

The schema execution shall use only this authorized representation.

## 13. TRANSACTION PLAN

The schema implementation shall execute inside one controlled PostgreSQL
transaction:

BEGIN
→ create authorized sequence
→ create authorized Patient table
→ create authorized constraints
→ verify expected objects within the transaction
→ COMMIT

Any execution error:

ROLLBACK

No partial schema increment may be accepted as proven.

---

## 14. IDEMPOTENCY / EXISTING OBJECT SAFETY

Before physical creation, the implementation must inspect whether the
authorized target objects already exist.

The implementation MUST NOT:

- drop an existing object;
- overwrite an unrelated object;
- mutate an existing unauthorized object;
- use destructive reset behavior.

If an authorized object already exists, execution must stop and reconcile
its actual structure against this plan rather than silently replace it.

After successful schema execution, proof shall establish:

2. Sequence starts at 1 and increments by 1.
3. `patients` exists.

5. CPN NOT NULL constraint exists.
6. CPN UNIQUE constraint exists.
7. Technical Patient identity remains distinct from CPN.
8. Only authorized physical objects were introduced.
9. No prohibited clinical objects were introduced.
10. No unrelated database was modified.
11. Schema execution completed atomically.
12. FAIL = 0.

## 19. FAILURE / ROLLBACK RULE

- wrong database;
- wrong PostgreSQL target;
- unexpected existing object;
- unauthorized object creation;
- unexpected constraint;
- unexpected physical decision;
- transaction failure;
- scope expansion;
- contract mutation.

The implementation must never continue past an unresolved boundary conflict.
