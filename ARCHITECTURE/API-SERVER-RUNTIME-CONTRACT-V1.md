# DR. ROBY CLINIC — API SERVER RUNTIME CONTRACT V1

STATUS = CONTROLLED TECHNICAL CONTRACT
SCOPE = CLINIC SERVER RUNTIME

## 1 PURPOSE

Defines the technical boundary of the Clinic API Server Runtime.

The runtime exists to expose authorized application/API behavior
over the already-defined Clinic domain and application contracts.

The runtime MUST NOT define or alter the product domain.

## 2 SERVER FRAMEWORK

API_SERVER_FRAMEWORK = FASTIFY

FRAMEWORK_DECISION_SOURCE = API-SERVER-FRAMEWORK-DECISION-V1.md
FRAMEWORK_RECONCILIATION = PASS

## 3 RUNTIME ENVIRONMENT

NODE_RUNTIME = EXISTING_TERMUX_NODE
NODE_VERSION = v26.4.0
PACKAGE_MANAGER = npm
PACKAGE_MANIFEST = PACKAGE_JSON
DEPENDENCY_MANAGEMENT = npm

PACKAGE_JSON_CREATION = DEFERRED_TO_IMPLEMENTATION_GATE
DEPENDENCY_INSTALLATION = NOT_IMPLEMENTED
SERVER_STARTUP = NOT_IMPLEMENTED

## 4 SERVER RESPONSIBILITY

SERVER_RUNTIME_RESPONSIBILITY =
- host the Clinic API runtime
- receive API requests
- dispatch requests to authorized application behavior
- return API responses
- participate in authenticated-request handling when separately authorized
- remain within established API and application boundaries

## 5 SERVER DOES NOT OWN

SERVER_DOES_NOT_DEFINE =
- Patient identity
- Case identity or lifecycle
- Visit meaning
- Clinic Day meaning
- Actor authority
- Doctor ownership
- Nurse clinical authority
- Product authorization policy
- Persistence truth
- UI behavior
- Deployment policy

## 14 IMPLEMENTATION GATE

This contract defines the runtime boundary.

It does NOT authorize:
- package.json creation
- Fastify installation
- dependency installation
- server source implementation
- server startup
- API route creation
- authentication implementation
- session implementation
- authorization implementation
- persistence implementation
- UI implementation
- deployment implementation

Implementation requires a separate build authorization gate.
